= IDEasy Team Setup
:toc:
toc::[]

This guide takes a new team member from a fresh machine to a working IDEasy development environment for the IDEasy project itself.
It is written to be handed to you as-is: follow the steps top to bottom and you will be able to open the code in your IDE, build it, and run the CLI.

If you just want to know *what you need* and *where everything ends up*, start with link:#prerequisites[Prerequisites] and link:#where-things-live[Where things live].
If a step does not work, link:#troubleshooting[Troubleshooting] is at the end.

NOTE: This guide lives in our internal Capgemini GitLab and may link to public GitHub documentation.
Public GitHub documentation must not link back to internal Capgemini resources, so the public docs will not cover our internal GitLab settings repository.

== Prerequisites

Before you start, sort out the accounts and tools you need and create your fork of the IDEasy code.
You do the account, token and fork setup *first* (once); everything else in this guide is then driven by `ide` commands.

* *Git* is installed and configured. +
If you do not have it yet, install it from https://git-scm.com/download/[git-scm.com]. +
Make sure your Git identity matches the GitHub account you will use to contribute (see next step):
+
[source,bash]
----
git config --global user.name "«your-name»"
git config --global user.email "«your-github-email»"
----

* *A GitHub account* (https://github.com/[github.com]). +
    This is where the IDEasy code lives and where you will fork, branch, and open pull requests. +
If you do not have an account yet, create one and then *send your GitHub login name via Teams chat to https://github.com/hohwille[hohwille]* so he can grant you the permissions you need in the `devonfw` organization. +
If you also use your Capgemini login as your GitHub login, your *operating-system username* (the `«username»` in `C:\Users\«username»`) usually matches your GitHub login — that is the value you will use as `GITHUB_USER` in the steps below.

* *A fork of the IDEasy repository* on GitHub. +
This is where you will push your branches and open pull requests from, so create it before you run `ide create`. +
On the https://github.com/devonfw/IDEasy[IDEasy] repository page, open the split button to the right of *Watch* (between *Watch* and *Star*) and choose **Create a new fork**. +
NOTE: If you are new to Git basics, the https://github.com/firstcontributions/first-contributions[first-contributions guide] is a good reference for forking, branching, and the Git commands used in this guide.

* *Access to the internal GitLab* at https://assets.engine.capgemini.com[assets.engine.capgemini.com]. +
This is where our *team settings* repository lives (the one this page is part of).
You need access to the `engine_hohwille/ideasy-settings` project.
If you cannot log in, this is an access problem — ask in the team channel before going further.

* *A personal access token for the internal GitLab.* +
We clone the settings repository over HTTPS, so Git needs a token instead of your password.
Create one **before** you run `ide create`:
+
. Open https://assets.engine.capgemini.com/-/user_settings/personal_access_tokens[Personal access tokens].
. Create a new token.
. Select the scopes `read_repository`, `write_repository`, and `api`.
. Create the token and copy it immediately — GitLab shows it only once.
+
IMPORTANT: Treat the token like a password.
Do not commit it, paste it into a shared file, or share it with anyone.

* *IDEasy* is installed and the `ide` command works in your terminal. +
Run `ide -v` to confirm.
If it is not installed yet, follow the link:#install-ideasy[Install IDEasy] section below first — everything in this guide assumes `ide` is available.

== How the pieces fit together

There are a few moving parts, so it helps to know which come preconfigured and which you actually set up yourself:

* The **settings repository** and the **team project variables** come preconfigured — `ide create` pulls them in for you, so you do not need to set them up.
* What you *actively* set up in this guide is: your GitHub **fork** (with `GITHUB_USER` as its user), your **personal** variable overrides (optional), and your **AI tooling**.

`GITHUB_USER` is simply your GitHub login.
IDEasy uses it in the team settings to clone your fork and set up the right remotes for you — you do not configure remotes by hand.
If your GitHub login is the same as your Capgemini / operating-system username, `GITHUB_USER` falls back to your OS username (`$USER`) automatically.

Throughout this guide, `$IDE_HOME` is your IDEasy home directory (e.g. `C:\Users\«username»\projects\IDEasy` on Windows).
You can find it with `ide status`, or print it with `echo $IDE_HOME` (bash) / `echo %IDE_HOME%` (cmd).

== Install IDEasy

Install IDEasy once, so that `ide create` works in the next section.
The fastest way is the one-line installer — it downloads the latest release,
extracts it, and adds the `ide` command to your shell:

. Open a bash terminal (on Windows: `Git Bash` from the Start Menu).
. Run:
+
[source,bash]
----
bash -c "$(curl -fsSL https://raw.githubusercontent.com/devonfw/IDEasy/main/install.sh)"
----
+
or download the package manually for your platform from the https://github.com/devonfw/IDEasy/releases[releases page] (MSI for Windows, PKG for macOS) and run it.

. Confirm `ide` is available:
+
[source,bash]
----
ide -v
----
+
NOTE: When you used the one-line installer, your *current* terminal will not pick up the
new `ide` command until its configuration is re-read.
run `source ~/.bashrc` (or open a new terminal ), this is a common reason `ide create`
appears to "not be found" right after installing.

For platform-specific notes (macOS Gatekeeper, proxy) see the
https://github.com/devonfw/IDEasy/blob/main/documentation/setup.adoc[full IDEasy setup guide].

== Create the IDEasy project

Now let IDEasy build your environment from the team settings.

. Open a terminal (on Windows open `Git Bash` from the Start Menu) and run:
+
[source,bash]
----
ide create IDEasy https://assets.engine.capgemini.com/engine_hohwille/ideasy-settings.git
----
+
Wait until it finishes — it takes several minutes the first time because it installs tools and plugins, clones the IDEasy code repository into your main workspace, and then builds it (the team settings define `build_cmd=mvn clean install`, which also runs the tests).
A successful build ends with a `BUILD SUCCESS` line.

. If Git asks for credentials (it will when it clones the settings or the code over HTTPS), enter:
+
* *Username:* your Capgemini email address or GitLab username.
* *Password:* the personal access token from the prerequisites step.
+
Do not enter your normal login password.
Depending on your Git credential configuration these may be stored securely, so you might not be asked again.

TIP: For the *code* repository (GitHub) the credentials are your GitHub ones, not the GitLab token.
If you are behind a corporate proxy or VPN and downloads fail, see the https://github.com/devonfw/IDEasy/blob/main/documentation/variables.adoc[variables guide] for `HTTP_VERSIONS` and proxy hints.

== Set up the code repository for contributing

To contribute, the remotes must point at your **fork** (which you created in the link:#prerequisites[prerequisites step]).

`ide create` already cloned **your fork** of the IDEasy code (using `GITHUB_USER`) into `$IDE_HOME/workspaces/main/IDEasy`, and added the official repository as `upstream` for you:

* `origin` → your fork (where you push and open pull requests from)
* `upstream` → the official `devonfw/IDEasy` (where you pull updates from)

NOTE: Make a quick verification that everything is set correctly using:

[source,bash]
----
git remote -v
----

== Open the project in your IDE

Start your IDE through `ide` so it picks up the project configuration:

[source,bash]
----
ide intellij
----

(`ide eclipse`, `ide vscode`, `ide pycharm`, and `ide android-studio` work the same way.)

The repository is imported into the IDE automatically during setup (the team settings configure the `import` variable for the IDEs to import into).
If the Maven structure is not picked up automatically, do *not* work around it by hand — that would hide the problem.
Instead file an issue, because the import is expected to work out of the box.

== (Optional) Configure your personal variables

You do not *need* to do this, the team settings in `settings/ide.properties` already work fine.
But IDEasy also reads a **personal** variables file at `$IDE_HOME/conf/ide.properties`, which lives only on your machine and is *never committed*.
Use it to override a value for yourself (e.g. to match how you work or to fix a local network issue).
Do not touch `settings/ide.properties` unless you are changing something for the whole team (that is a settings-repo change and goes through Git).

The file is created for you on first run; open it and uncomment the lines you need.
For the full list of variables and examples (e.g. proxy/VPN settings, `PREFERRED_GIT_PROTOCOL`, `M2_REPO`) see the https://github.com/devonfw/IDEasy/blob/main/documentation/variables.adoc[variables guide] and the header comment at the top of `conf/ide.properties`.

The one you will most likely set is `GITHUB_USER` — your GitHub login, which IDEasy uses to clone your fork (see the link:#set-up-the-code-repository-for-contributing[previous step]).
If your GitHub login is the same as your OS username you can reference it instead of typing it:

[source,properties]
----
# your GitHub login:
GITHUB_USER=«your-github-login»
# or, if it matches your OS username:
#GITHUB_USER=${USER}
----

NOTE: Change personal variables only if you understand the effect.
A wrong value in `conf/ide.properties` affects only your machine, but it can still break your build — when in doubt, leave it as-is and ask in the team channel.

== Set up AI tooling

AI plugins (e.g. GitHub Copilot for IntelliJ, Copilot for VS Code) are installed automatically from the settings during `ide create`.
For **Claude Code** we also have the company-provided installer *binary* of the Capgemini Sovereign AI Platform,
see the link:https://docs.sovai-de.apps.ce.capgemini.com/sovai/platform-user/agentic-coding/claude-code.html[Claude Code installation docs].

. Install Claude Code.
For the current use in IDEasy it is sufficient to install it through the `ide install` command (the team settings already include it in `IDE_TOOLS`, so `ide create` installs it for you).

. Let IDEasy apply the configuration.
On `ide create` (and `ide update`) IDEasy copies the `templates/conf/claude/settings.json` template from the settings repository into your `$IDE_HOME/conf/claude/` folder, and Claude Code reads it from there.
It sets the `ANTHROPIC_BASE_URL`, the model aliases and the CA certificate for you, and pulls in your AI token through the `$[secret:ai-api-key]` function as `ANTHROPIC_AUTH_TOKEN`.
So the token is asked for by a function — you never type the endpoint, the model list, or the API key by hand.

. Confirm it works:
+
[source,bash]
----
claude --version
----
+
Then start it (`claude`) and you are set.

NOTE: If the installer or your authentication does not behave as expected, re-read the internal docs page above and check in the team channel — everyone uses the same setup, so this is an easy question to clear there.

== Troubleshooting

Use this section only if the setup above does not complete cleanly.

=== Verify the settings repository remote

Navigate to the settings repository and inspect its remote configuration:

[source,bash]
----
cd "$IDE_HOME/settings"
git remote -v
----

The expected remote is:

[source,text]
----
origin  https://assets.engine.capgemini.com/engine_hohwille/ideasy-settings.git (fetch)
origin  https://assets.engine.capgemini.com/engine_hohwille/ideasy-settings.git (push)
----

If `origin` points at a different repository, correct it:

[source,bash]
----
git remote set-url origin https://assets.engine.capgemini.com/engine_hohwille/ideasy-settings.git
git remote -v
----

=== Check the code repository remotes

In the code repository you want `origin` to be your fork and `upstream` to be the official repo:

[source,bash]
----
cd "$IDE_HOME/workspaces/main/IDEasy"
git remote -v
----

Expected: `origin` → `https://github.com/«your-github-login»/IDEasy.git` (your `GITHUB_USER`) and `upstream` → `https://github.com/devonfw/IDEasy.git`.
If `origin` does not point at your fork, make sure `GITHUB_USER` is set correctly in `conf/ide.properties` (see the link:#optional-configure-your-personal-variables[personal variables] section), then re-apply the settings with `ide update`.

=== Clear expired or incorrect HTTPS credentials

If Git reports an authentication failure although the remote URL is correct, remove the stored credential:

[source,bash]
----
printf "protocol=https\nhost=assets.engine.capgemini.com\n\n" | git credential reject
----

Then test access again:

[source,bash]
----
git fetch origin
----

When prompted, enter your Capgemini email address or GitLab username as the username and your personal access token as the password.

=== Personal access token problems

Authentication can fail when:

* the token has expired;
* the token was revoked;
* the token was copied incorrectly;
* the required repository scopes are missing;
* the GitLab account does not have access to the settings repository; or
* an outdated token is still stored by the Git credential manager.

Create a new token if required, clear the previously stored credential, and retry `git fetch origin`.

=== Configure upstream tracking

If Git reports that the local `main` branch has no upstream branch, run:

[source,bash]
----
git checkout main
git branch --set-upstream-to=origin/main main
----

Then retry the update:

[source,bash]
----
ide update
----

=== Setup was created with the wrong settings repository

If the project was initially created with an incorrect settings repository:

. Correct the `origin` URL as described above.
. Verify access with `git fetch origin`.
. Run `ide update` from the IDEasy project directory.

If the update still fails, read the complete Git error message to determine whether the problem concerns authentication, repository access, the remote URL, network connectivity, or branch tracking.
